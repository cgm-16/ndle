### The pre-flight rulings, R1–R4

The 11-11 and 11-16 journals cite these as "(R1)", "(R2)" and "(R3)".

- **R1:** `ActionButton` takes a `className`, appended after its own
  classes. Each screen then sets its buttons' height and type in its own
  module, not as an inline `style`.
- **R2:** T109 could edit any component stylesheet that read a token it
  deleted or renamed, or that drew its own focus ring, but only those
  declarations.
- **R3:** in overflow, `OverflowControls` is the band's left cell and its
  `role="status"` region, so each phase has one live region with content.
  - Its other half, that FeedbackPanel is not rendered in overflow, was
    replaced in T114: both status regions stay mounted.
- **R4:** each layout task (T111–T115) stops and reports measured heights if
  a state can't fit. It may not shrink type or loosen a check, because the
  plan's margins were arithmetic, not measured. No task hit the stop.

### Design calls left standing

- **The miss stroke stays one diagonal per tile.** The brief allowed either
  reading, and the reviewer didn't block it.
  - The slots' settle count, which feeds the auto-advance after a discard,
    counts one stroke per tile (`AnswerSlots.tsx:89-91`,
    `GameScreen.tsx:44-45`).
  - A single stroke across the row would mean reworking that count. It is
    Ori's to veto.
- **The rail cell stays 88 px.** The tilt it made room for went in T116, but
  88 px is T114's brief value, and the viewport check pins it. Shrinking it
  would give the band 22 px.
- **The toggle's `.button:last-child` picks the Hangul half by position.**
- **The flecks check has no pin against stale reads.** It reads the tiles at
  each seeked time. The flecks clear the tiles by more than 4 px, so a
  return to reading the rectangles once would still pass, and that
  regression would go unseen.
