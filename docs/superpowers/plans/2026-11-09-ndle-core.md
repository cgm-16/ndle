# ndle Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task by task.
> Task steps live in `docs/tasks/T91..T108.md` and use checkbox (`- [ ]`)
> syntax for tracking.

**Goal:** Turn the seeded ozterisk tree into **9dle** (구들), a daily
multiplication puzzle with a Practice mode. Its rules are rewritten, Puzzle is
its only mode, a year of solver-chosen daily tables ships, and a Daily resumes
after a reload. It all runs on placeholder visuals until the identity is
approved.

**Architecture:**
- The game is M8's Puzzle with the mode axis removed. `gameReducer` stays pure
  and knows nothing of dates, storage or Daily versus Practice.
- Which table a run plays is decided at the App boundary:
  - **Daily:** today's number, from an injected clock and a launch date, picks
    a table from a shipped JSON list.
  - **Practice:** `dealPuzzle(Math.random)`.
- A Daily is saved as its table number, its moves so far and its outcome. A
  reload replays the moves through the real reducer.
- An offline generator, run through Vite's `runnerImport`, plants and solves
  tables to fill the list.

**Tech Stack:** Vite, React 19 `useReducer`, TypeScript, CSS Modules, Vitest
and React Testing Library, and Playwright for geometry only, all unchanged.
The one dependency change is that `@fontsource/gothic-a1` replaces ozterisk's
four font packages (T100).

**Spec:** [`2026-11-09-puzzle-spin-off-design.md`](../specs/2026-11-09-puzzle-spin-off-design.md),
copied verbatim from ozterisk `main` at `c212fcd` in T91. It argues from M8's
rules, [`2026-10-19-puzzle-prototype-design.md`](../specs/2026-10-19-puzzle-prototype-design.md)
§3–§7.

**Handover:** `puzzle-spin-off-handover.md`, Ori's local brief. It is not
committed.

**Second plan:** the restyle, the two layout fixes, the Korean screen, the
geometry suite for every screen, the launch date and the first release. It is
written after the identity and screens are approved, as milestone `M16`, with
one tracking issue (`docs/plan/github.md` §4.5).

## Global Constraints

Every task inherits these. Values are copied from the design.

- **Name:** **9dle** in English, **구들** in Korean, `ndle` as the slug
  (repo, package name, storage keys and identifiers). The visible wordmark is
  a placeholder until the second plan.
- **Rules are M8's, unchanged** (design §2.1).
  - Five distinct opening digits and eight rows.
  - A pay of 2 for a one-digit product and 3 for a two-digit product.
  - Capacity 5.
  - A wrong answer is legal.
  - The run ends after row 8, or earlier when the hand holds **fewer tiles
    than the next answer needs**. A hand with enough tiles but the wrong
    digits plays on.
- **No dial changes value** (AGENTS.md §4.5). `PUZZLE_MIN_PAR` 7 and
  `PUZZLE_MIN_ONLY_MOVES` 2 define the band for both Practice and the daily
  list.
- **The reducer stays pure:** no randomness, no date and no storage in
  `src/game/gameReducer.ts`. The date picks the daily table at the boundary.
- **Client-only:** no backend, accounts, analytics, leaderboards, daily
  streak or result URLs.
- **Storage** holds the language and today's daily (its table number, its
  moves so far and its outcome), and nothing else.
- **The daily share text** gives the table number, the score against par and
  the game's link. It never gives the rows.
- **Practice** deals live, with `dealPuzzle(Math.random)`. A Practice table
  can never be replayed or shared.
- **Daily slots freeze once their date arrives**, and a veto touches only
  future slots. The launch date is set once and never changes after launch.
- **Self-hosted fonts and zero non-origin requests.** English and Korean go
  through the typed dictionary in `src/i18n/messages.ts`; every new string
  gets an `en` and a `ko` entry.
- **State is never shown by colour alone.** Text contrast is at least 4.5:1,
  and touch targets are at least 44 px.
- **No sound and no animation library.** Motion is limited to the keyframe
  inventory in `docs/spec/ui-i18n.md` §1.12.
- **Tests:** test-first with Vitest and RTL. The browser suite (`e2e/`)
  asserts geometry only, and any spec there that needs a fixed table reads a
  gallery state.
- **Gates for every task:** `npm run lint`, `npm run typecheck`,
  `npx vitest run --reporter=default` (output read in full) and
  `npm run build`. From T95 on, `npm run test:e2e` too. Before each command,
  run `eval "$(fnm env --shell bash)" && fnm use 24`.
- **Git:**
  - One branch per milestone, `feat/M#-kebab-name`, cut from `main`.
  - One Conventional Commit per task, with `Task: T##` in its body.
  - The PR title is `[M#] …`, and the body has a `Closes #N` line for each
    task issue.
  - Never commit to `main` or `prod`, and never use `git stash`.
  - Agent shells push over HTTPS through gh:
    `git -c credential.helper= -c credential.helper='!gh auth git-credential' push https://github.com/cgm-16/ndle.git <branch>`.
  - A diff that touches `.github/workflows/*` goes to Ori as an exact SSH
    push command.

## Review Focus

Failure modes the design implies but no headline test reaches. Each one has
its test in the task named.

1. **Tile IDs after a replay.**
   - The reducer silently refuses `SUBMIT_CORRECT` when a reward tile's ID is
     already in the hand.
   - So a replay must draw IDs from the same `nextTileId` that live play then
     continues with. Otherwise the first correct answer after a reload does
     nothing.
   - Pinned in T104, which replays three moves and then submits a correct
     answer live, and in T107 through the UI.
2. **A refused action means a bad record.**
   - The reducer returns the same state object when it refuses an action.
   - A replay that sees this returns `null` and does not build a wrong state.
   - Pinned in T104, using a move that spends a digit the hand lacks.
3. **A reload between submit and discard lands in overflow,** row 8 included,
   since the par line overflows on rows 4–8.
   - The replay must not send `NEXT_ROUND` for a move with no discard that
     left the hand at six.
   - Pinned in T104: the par line with row 8's discard removed ends in
     `overflow`, not `gameOver`.
4. **Nothing restarts a Daily.**
   - `R`, Play Again and `RESTART_RUN` are each a way around the one-attempt
     rule today.
   - Pinned in T107: at a Daily game over, `R` is ignored, there is no Play
     Again, and a reload shows the same result.
5. **Moves are recorded once under StrictMode.**
   - A save from an effect or from render runs twice in dev.
   - Pinned in T107: a StrictMode render that plays three rows saves exactly
     three moves.

The tasks also pin these:
- Practice never writes the daily record (T107).
- The same local date always gives the same number, across DST changes and
  midnight (T101).
- Before launch or past the end of the list there is no daily table, and
  Practice still opens (T103 and T106).
- A daily share text never names a row, which T108's exact-string tests show.
- A corrupt or foreign record in storage is ignored without a crash (T105).
